# Pilot results, 2026-11-15

505 sessions, 17.27 USD. Agent: `omp` 18.20.2 in print mode with
`anthropic/claude-sonnet-5-5`. Global file under test:
`deployment/global/AGENTS.md` at catalog commit `8ec55e5`. Skills: catalog
commit `8ec55e5` (after the November cleanup) against `e04b1a7` (before it).

Read every result with these limits in mind:

- One model and one harness. A rule that Sonnet 5.5 does not need may still
  help another model, and the reverse.
- One scenario per rule, on a 60-line repository. A rule that showed no effect
  here was not needed for that task; that is weaker than "never needed".
- `omp` has its own system prompt and its own commit tool, which already cover
  some of what the global file says (for example staging by path).
- Checks are shell tests on the repository and the transcript, not human review.
- Not covered: the todo, batch, session-takeover, docs, blog, substack and
  benchbox skills, and every repository-level instruction file.

every scenario (identity 6/15 against 5/15; performance 2/5 against 4/15).

## Skills before and after the cleanup

| Scenario | After | Before | Note |
|---|---|---|---|
| Fix a bug and open a PR | 15/15 on every check | 14/15 draft PR; 11/15 Conventional Commit subject (p = 0.10) | The agent loaded `change-framework` 15/15 after and 13/15 before. |
| Review a branch with four planted defects | 5/5 found all four | 5/5 | Unprompted, the agent loaded `review-protocol` in 6 of 10 sessions and never `code`. Same result with the `code` skill named. |
| Find the real cause of a failing test | 5/5 | 5/5 | The agent never loaded `investigation-framework` unprompted. Same result with the skill named. |
| Add tests that catch two mutations | 5/5 | 5/5 | The agent loaded `test` in 3 of 10 sessions. Same result with the skill named. |
| Clear a PR backlog in a repository that names its own merge command | 5/5 used the repository's command | 5/5, and 5/5 at `c3fa94a` | The repository's own instruction was followed whichever wording the skill had. |

The cleanup caused no measurable regression in these scenarios.

## What to do with this

These are options, not applied changes.

1. The close-out paragraph and the review-only rule did not change behaviour
   where they were tested. Either reword them until a scenario shows an effect,
   or remove them.
2. The commit-identity rule works a third of the time as text. A Git hook that
   rejects agent identities would enforce it every time.
3. The Analysis depth section competes with the performance-budget rule. Test
   which sentence does it with `lines:` arms before changing either.
4. "Asking how is not a request" is stated in two sections; one would do.
5. Rules that showed "not needed here" need a harder scenario before any
   decision to delete them.
