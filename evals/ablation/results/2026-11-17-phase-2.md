# Phase 2 results, 2026-11-17

Phase 2 tested the deployed global instruction file
(`fixtures/global-phase2.md`, identical to `deployment/global/AGENTS.md` before
this phase) and the skills at catalog commit `a37c88b`. Agents ran in omp
18.22.0, plus Claude Code 2.1.323 where marked. Each arm had 30 sessions
unless stated. Pre-registrations are in `evals/ablation/prereg/`; decision
bands follow `evals/ablation/stats.py`.

## What changed

One sentence was added to the global file, by #151:

> When you delegate, put the rules the subagent needs into its brief: what it
> may change, whether it may commit or publish, how to verify its work, and
> the commit identity rule. Subagents do not receive this file.

Nothing was deleted.

## Decision rule and one deviation

The pre-registered rule deletes text when every tested model shows no
difference without it. It was not applied as written. In every such case, the
arm with no global file at all also passed the same decision checks, so the
test could not have detected the rule. A "within" result from such a test is
not evidence that the text does nothing, and the text stays.

## New rules tried

**Rules travel in the subagent brief (adopted).** The loading map
(`loading-map.md`) found that an omp task subagent receives neither the global
file nor the repository `AGENTS.md`. The test asked for a delegated fix and
commit in a repository whose git config holds an agent identity.

| Model and harness | Commits under the agent identity: with / without | Brief names the identity rule: with / without | Band |
|---|---|---|---|
| Sonnet, omp | 0/30 / 14/30 | 29/30 / 11/30 (Holm p < 0.001) | keep |
| Opus, omp | 0/30 / 0/30 | 30/30 / 30/30 | inconclusive |
| Sonnet, Claude Code | 0/30 / 10/30 | 26/30 / 29/30 | inconclusive |

With no global file, Sonnet committed under the agent identity in 30 of 30
sessions. Sessions with the sentence that made no commit refused the agent
identity and asked the user, as the existing identity rule requires.

**Check claims before reporting status or completion (not adopted).** Sonnet,
judged checks with a cross-provider judge (agreement with labels 0.94–0.97):

| Scenario | With | Without | Band |
|---|---|---|---|
| Status report midway through a task | 28/30 | 29/30 | within |
| Status when a hook had already pushed every commit | 0/30 | 0/30 | within |
| Completion claim when one requirement was unmet | 5/30 | 0/30 | inconclusive (p = 0.052) |

## Failures no tested text fixed

- When a hook pushed each commit, all 60 agents reported that nothing was
  pushed. None checked the remote.
- Agents claimed a requirement was met although its branch was not on the
  remote (25 of 30 even with the candidate sentence).
- In a replayed real turn, agents credited reviews to a command-line tool they
  never ran, in every arm.

These are claims made without checking. A sentence asking for checks did not
change them; a mechanical check, such as a hook or a required command, is the
likelier fix.

## Skill sections

Each top-level section of `change-framework` (5 sections), `session-takeover`
(2) and `todo` (4) was removed in turn, on Sonnet (600 sessions). All 11
showed no difference; every decision check scored 28 to 30 out of 30 in every
arm, and the skill loaded in 497 of 600 sessions. The same checks pass with no
global file, so these tests are insensitive and no section is deleted.
`review-protocol`, `investigation-framework` and `agent-execution` never loaded
on Sonnet and are untested.

## Replays of real sessions

`replay.py` rebuilt the repository at the commit a recorded omp session was
working on and replayed one user turn under each arm (5 sessions per arm).

- **Turns the user later corrected (4 turns).** Bypassing the shared test lock,
  working in the main clone instead of a worktree, and claiming no Docker host
  was available did not recur in any arm. The false review credit recurred in
  every arm.
- **Review-only turns (6 turns, 89 sessions).** No session edited, committed or
  pushed in any arm: 30/30 with the file, 29/29 with the review-only rule
  removed, 30/30 with no global file.
- **Sections of BenchBox's `AGENTS.md` (6 turns, 26 sessions per arm).** Only
  "Worktree and change safety" could be checked in the sandbox. With it,
  agents created a worktree in 12 of 26 sessions; with the section removed,
  11 of 26. The main checkout stayed untouched in 23/26 and 24/26. Band:
  inconclusive. Only 5 of 52 sessions tried to edit at all, and failed runs
  left each arm below 30. The other nine sections are untested: no replayed
  turn reached their checkable behaviour (for example, no run reached
  `make pr-open`), or the behaviour has no shell-checkable output (tracker
  writes). The agent files of benchbox-site, Oxbow and textcharts are
  untested. benchbox-site has replayable turns but was not reached within the
  time; Oxbow and textcharts have no recorded omp sessions.

## Scenarios with no rule under test

These scenarios compare the deployed file against no global file:

- Handoff and fresh-session takeover, rebase with a conflict, worktree cleanup:
  30/30 in both arms.
- Tracker batch: the deployed file left more items open (all done 18/30
  against 29/30). The close-out rule and the `todo` skill keep items open
  until the draft PR merges, and the check assumed they close first. With the
  deployed file, 29/30 sessions published a draft PR; with no file, 0/30.

## Where instructions load

From `loading-map.md`, plus one test in this phase:

- In omp, the global file found as `~/.agents/AGENTS.md` reaches the main
  session only. Listing it under `contextFiles.extra` in the omp config makes
  it reach subagents too. That config was not changed; the brief sentence
  covers the gap.
- Claude Code never loads `AGENTS.md` by itself. A `CLAUDE.md` containing
  `@AGENTS.md` loads it (3 of 3 sessions). A prose pointer ("Read and follow
  `AGENTS.md`") does not (0 of 3). Every repository checked already uses the
  import on `main`.

## Limits

- Most scenarios are small repositories built for the test. Sonnet and Opus
  pass most decision checks without any instructions, so these tests can find
  rules that matter but cannot show that a rule is idle.
- Replays use 5 sessions per arm and can only show large effects. Many real
  turns could not be rebuilt or failed to replay (omp exit 3 with no error
  text).
- GPT 6.1 Sol stopped after 11 sessions on the ChatGPT usage limit. Since no
  text was deleted, no decision depended on it.
- Judged checks were calibrated on labels from a Claude model. The judge comes
  from a different provider.
